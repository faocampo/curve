## Purpose and boundaries

This contract fixes the PostgreSQL representation and transaction invariants
required by `M0-S2 (operation and delivery kernel)`. PostgreSQL is authoritative
for every record below. Plane remains authoritative for workspace identity and
membership; Curve stores `workspace_id` as an opaque UUID and creates no hard
foreign key to a Plane table.

The package persists only synthetic `INTERNAL` metadata. Protected bodies,
object storage, Temporal, network delivery, provider callbacks, general policy
adapters, and staging or production activation are outside this contract.

## Tables and lifecycle ownership

| Table/model | Lifecycle | Required role |
| --- | --- | --- |
| `curve_operation` / `Operation` | Mutable aggregate root with optimistic versioning and tombstone fields | Represents one asynchronous command and its safe result/error projection. |
| `curve_domain_event` / `DomainEvent` | Append-only | Durable event envelope written atomically with the accepted aggregate mutation. |
| `curve_outbox_event` / `OutboxEvent` | Mutable delivery state | Claims, retries, acknowledges, or dead-letters one durable event for one destination. |
| `curve_inbox_message` / `InboxMessage` | Mutable deduplication state | Ensures one consumer applies one durable event at most once. |
| `curve_idempotency_record` / `IdempotencyRecord` | Mutable until terminal; terminal records are immutable | Replays the original safe database resource for the same command request. |
| `curve_audit_event` / `AuditEvent` | Append-only | Records attributable allowed, denied, successful, failed, and no-effect actions. |

`DomainEvent` and `AuditEvent` reject update and delete through the application
repository. Their database rows are never rewritten by M0-S2. Later retention
or erasure behavior requires `D-009 (retention, deletion, backup, and legal-hold
decision)` and a separate migration/contract.

## Approved key and reference representation

1. A command accepts an idempotency key only in process memory, computes
   `sha256:<lowercase-hex>`, and immediately discards the raw value. Only
   `key_digest` is persisted or logged.
2. `request_digest` and `response_digest` are SHA-256 digests of versioned,
   deterministic canonical JSON bytes.
3. `response_resource_ref` is a `ResourceRef` to a safe PostgreSQL resource,
   initially the resulting `Operation`. It is not an object-storage reference.
4. Actor, target, effective-principal, safe-error, and resource references use
   the corresponding JSON Schema shapes. Indexed identity components are also
   stored in normalized columns where this contract requires uniqueness.
5. Every primary key is a UUID generated by the application. Every timestamp is
   timezone-aware UTC. Database comparisons use PostgreSQL time.

## Exact uniqueness and workspace boundaries

| Record | Database uniqueness constraint |
| --- | --- |
| `DomainEvent` | `(workspace_id, aggregate_type, aggregate_id, sequence)` |
| `AuditEvent` | `(workspace_id, target_type, target_id, sequence)` |
| `OutboxEvent` | `(workspace_id, event_id, destination)` |
| `InboxMessage` | `(workspace_id, consumer_id, event_id)` |
| `IdempotencyRecord` | `(workspace_id, principal_scope, command_scope, key_digest)` |

All repositories and command services require `workspace_id` as a non-optional
argument and include it in the first database predicate. Cross-workspace IDs
produce the same not-found result as an absent ID. The service validates that
referenced Curve records carry the same workspace before a write.

Per-aggregate event sequences are allocated while the aggregate row is locked.
Audit sequences use a PostgreSQL transaction-scoped advisory lock derived from
`workspace_id`, `target_type`, and `target_id`, followed by `MAX(sequence) + 1`.
The unique constraints remain the final race fence. A uniqueness conflict is
retried only inside the bounded command transaction and never after an external
effect.

## State-dependent database checks

| Record/state | Required non-null fields |
| --- | --- |
| Terminal `Operation`: `SUCCEEDED`, `FAILED`, `CANCELLED` | `completed_at`; `FAILED` also requires `error` |
| `OutboxEvent.CLAIMED` | `claimed_by`, `claimed_until` |
| `OutboxEvent.RETRY_SCHEDULED` | `next_attempt_at`, `last_error` |
| `OutboxEvent.DELIVERED` | `delivered_at` |
| `OutboxEvent.DEAD_LETTER` | `last_error` |
| `InboxMessage.PROCESSED` | `processed_at`, `result_digest` |
| `InboxMessage.FAILED_TERMINAL` | `processed_at`, `last_error` |
| Terminal `IdempotencyRecord`: `COMPLETED`, `FAILED_TERMINAL` | `response_status`, `response_digest`, `response_resource_ref`, `completed_at` |

The migration implements equivalent `CheckConstraint` expressions. Fields may
remain nullable in non-applicable states; a state transition cannot commit a
state-required null.

## Command transaction

One accepted operation command executes in a single `transaction.atomic()`
boundary:

1. Resolve Plane identity and membership before the Curve service is called.
2. Require `workspace_id`, actor/effective principal, command type, target,
   correlation ID, expected aggregate version when mutating, raw idempotency key,
   and canonical request bytes.
3. Compute the key/request digests and lock or create the exact idempotency scope.
4. If the same key and digest already completed, resolve and return
   `response_resource_ref` without another domain effect.
5. If the same key has a different request digest, append a safe `NO_EFFECT`
   audit event and return the stable `409` result.
6. Validate the expected aggregate version. A stale version returns `412`,
   appends the required safe audit record, and writes no domain event or outbox
   event.
7. Persist the accepted `Operation` mutation, `DomainEvent`, `OutboxEvent`,
   successful `AuditEvent`, and completed `IdempotencyRecord` atomically.
8. Return only after commit. No network, Temporal, provider, VCS, object-storage,
   or broker call occurs inside the transaction.

A database exception rolls back every effect in the transaction. A response is
never cached as successful before its referenced resource is durable.

## Relay primitives

The local relay repository claims due rows with one atomic PostgreSQL selection
using `SELECT ... FOR UPDATE SKIP LOCKED`, changes them to `CLAIMED`, increments
`attempt_count`, and writes a bounded lease owner/deadline. Two claimers cannot
return the same active claim.

- `ack`: a matching active claim becomes `DELIVERED` with non-null
  `delivered_at`.
- `retry`: a matching active claim becomes `RETRY_SCHEDULED` with non-null
  `next_attempt_at` and a safe error.
- `dead_letter`: a matching active claim becomes `DEAD_LETTER` with a safe error.
- expired claim: becomes due again through an explicit recovery operation; the
  prior attempt remains represented by `attempt_count` and audit metadata.

M0-S2 exposes these as repository/application-service primitives only. Network
delivery begins in a later package.

## Migration and verification obligations

The Plane implementation must provide:

1. Curve-only tables, indexes, foreign keys between Curve records where safe,
   uniqueness constraints, and state-dependent check constraints.
2. Forward, backward-to-zero, and forward-again migration proof on a disposable
   PostgreSQL database, with generated SQL retained in PR evidence.
3. Tests for same-key replay, changed-digest conflict, stale-version rollback,
   cross-workspace non-disclosure, atomic rollback, immutable events/audits,
   uniqueness constraints, two-claimer exclusion, ack/retry/dead-letter, and
   expired-claim recovery.
4. JSON Schema conformance for every serialized record and semantic negative
   fixtures for state-required null fields and raw idempotency-key persistence.
5. Full Plane backend, `pnpm check`, and `pnpm build` regression evidence.
