## Purpose

This contract makes M0-03 (core authorization and policy kernel) executable in
the public Plane fork. It defines the one new persisted record, the policy
evaluation boundary, transaction behavior, workspace lookup order, migration,
and database evidence required before later domains may rely on Curve
authorization.

Plane remains authoritative for human authentication and active workspace
membership. M0-03 does not copy Plane memberships, create general Curve role
assignments, persist object ACLs, or select provider-specific authorization.
Later aggregate owners supply versioned gate assignments and object ACL metadata
to the same evaluator. Provider adapters may add only separately approved,
narrower policy after their consuming decision is `DECIDED`.

## Physical record

### `curve_policy_decision`

`PolicyDecision` is append-only and stores only safe authorization metadata. It
contains no evidence body, prompt, source excerpt, provider credential, object
body, user token, or raw idempotency key.

| Column | PostgreSQL type | Null | Constraint and meaning |
| --- | --- | --- | --- |
| `id` | `uuid` | No | Primary key generated by the trusted API process. |
| `schema_version` | `varchar(20)` | No | Exactly `1.0` for this contract. |
| `workspace_id` | `uuid` | No | Requested/owning Plane workspace scope; first predicate for every query. |
| `sequence` | `bigint` | No | Positive, monotonically increasing per workspace/resource; allocated under the same transaction lock used for immutable audit ordering. |
| `action` | `varchar(128)` | No | Stable action from the approved manifest. |
| `resource_type` | `varchar(100)` | No | Stable uppercase resource code. |
| `resource_id` | `uuid` | No | Requested Curve/Plane resource identity; never used without `workspace_id`. |
| `resource_version` | `bigint` | Yes | Positive when known; absent for a pre-resource workspace-bound denial. |
| `subject` | `jsonb` | No | Validated `ActorRef` for the authenticated actor. |
| `effective_principal` | `jsonb` | No | Validated `ActorRef`; equal to subject in M0 unless a later decided delegation contract applies. |
| `effect` | `varchar(32)` | No | `ALLOW`, `DENY`, or `REQUIRE_HUMAN_CONFIRMATION`. M0 core rules produce `ALLOW` or `DENY`; the third value is reserved for later approved workflows. |
| `reason_codes` | `jsonb` | No | Non-empty unique ordered stable codes; order follows manifest deny precedence. |
| `policy_key` | `varchar(100)` | No | Exactly `CURVE_CORE_POLICY`. |
| `policy_version` | `positive integer` | No | Exactly `1`. |
| `policy_manifest_digest` | `varchar(71)` | No | SHA-256 of exact UTF-8 manifest bytes. |
| `input_digest` | `varchar(71)` | No | SHA-256 of canonical safe evaluation input; protected content is absent before hashing. |
| `normalized_classification` | `varchar(20)` | No | `INTERNAL`, `CONFIDENTIAL`, or `RESTRICTED`; `UNKNOWN` input becomes `RESTRICTED`. |
| `permitted_projection` | `jsonb` | No | Non-empty manifest projection on `ALLOW`; empty for every other effect. |
| `correlation_id` | `varchar(255)` | No | Safe request/command correlation identifier. |
| `evaluated_at` | `timestamptz` | No | Trusted server time in UTC. |
| `recorded_at` | `timestamptz` | No | Database recording time in UTC. |
| `recorded_by` | `jsonb` | No | Validated trusted `SERVICE` or `SYSTEM` actor that persisted the result. |

Required indexes and constraints:

1. Primary key on `id`.
2. Unique constraint on `(workspace_id, resource_type, resource_id, sequence)`.
3. Index on `(workspace_id, evaluated_at DESC)`.
4. Index on `(workspace_id, resource_type, resource_id, evaluated_at DESC)`.
5. Index on `(workspace_id, effect, evaluated_at DESC)` for security review.
6. `sequence >= 1` and `resource_version IS NULL OR resource_version >= 1`.
7. `effect = 'ALLOW'` requires a non-empty JSON array in
   `permitted_projection`; any other effect requires an empty array.
8. `reason_codes` is a non-empty JSON array.
9. Both digests match `^sha256:[0-9a-f]{64}$`.
10. `recorded_by.actor_type` is `SERVICE` or `SYSTEM`.
11. `recorded_at >= evaluated_at`.
12. `PolicyDecision` rejects instance update/delete and queryset update/delete.
13. M0-03 creates no hard foreign key to Plane tables. The opaque
    `workspace_id` boundary approved by D-001 (Plane foundation, licensing, and
    fork decision) remains unchanged.

## Evaluator inputs and ownership

The evaluator consumes exactly the
[policy evaluation schema](../schemas/policy-evaluation.schema.json) (safe,
versioned authorization input). This is an internal trusted-service contract,
not a public request body. HTTP, MCP, provider, model, retrieved, and agent input
cannot supply or override roles, membership, resource workspace/owner, ACL,
assignment, classification, allowlist, service authorization, manifest digest,
or effective principal. The trusted context builder resolves every field from
the authoritative producer below:

| Input | Authoritative producer | M0-03 rule |
| --- | --- | --- |
| `subject` | Plane authentication | Required; anonymous input denies. |
| `effective_principal` | Curve request boundary | Equals subject in M0; a service may supply itself only with a matching unexpired service authorization. |
| `membership` | Live Plane `WorkspaceMember` query for a human | Active and workspace-equal for `HUMAN`; exactly `null` for `SERVICE`, `SYSTEM`, or `AGENT`; no independent Curve membership cache. |
| `roles` | Resolver combining membership and later versioned assignments | M0 maps active membership to `WORKSPACE_MEMBER`; unimplemented roles are absent rather than inferred. |
| `resource` | Workspace-scoped metadata query or safe request reference on an early denial | Exact type, requested workspace, ref, existence, and owner. Query uses `(workspace_id, id)` only; not-found remains non-disclosing and the protected body stays unloaded. |
| `object_acl` | Owning aggregate metadata | Exact workspace/resource/version binding. ACL only narrows an already allowed role/action. A required missing ACL denies. |
| `assignment_context` | Owning Initiative/Gate aggregate in later milestones | Exact workspace/subject/version binding. Exact human assignment and risk-tier separation are required for gate actions; unrelated actions use `null`; missing required context denies. |
| `classification` | Owning resource metadata | `UNKNOWN` normalizes to `RESTRICTED`; callers cannot lower it. |
| `target_context` | Approved workspace/provider/repository configuration | Exact workspace binding. A required empty allowlist denies. Prompt or retrieved content cannot add a target. |
| `service_authorization` | Trusted Curve controller boundary | Exact authorization ID, workspace, service, live active state, action, issue time, and expiry; absent, revoked/inactive, future-issued, or expired input denies service access. |
| manifest digest | Byte-pinned contract copy | Must equal the runtime manifest bytes before serving Curve traffic. |

## Deterministic decision order

Evaluation is pure and follows the manifest's ordered fail-closed predicates:

1. Validate the schema and exact manifest digest.
2. Require the Curve feature to be enabled for the requested workspace.
3. Require an authenticated actor and reject `AGENT` globally with
   `AGENT_NOT_ALLOWED`.
4. Require equality among requested workspace and resource workspace. For a
   human, also require an active live membership in that exact workspace. For a
   non-human actor, membership must be absent.
5. Resolve the action by exact string. Missing actions deny; wildcard and prefix
   matching are forbidden.
6. Require the exact resource type to be allowed for the action, then require the
   workspace-scoped resource to exist. A missing resource and an ID that exists
   only in another workspace both deny without a global fallback lookup.
7. Require the subject/effective-principal actor type to be allowed for the exact
   action. In M0 they must be equal; a service must also match the service
   authorization identity checked below.
8. Require at least one allowed role. A Plane workspace role alone never grants
   an approver or platform role.
9. Require the environment and normalized classification to be allowed.
10. Apply object ACL. Reject any workspace/resource/version mismatch. Principal
   or role deny entries win. Allow entries can only
   narrow the role result. For `REQUIRED`, a missing/empty non-owner allow set
   denies. Resource ownership may satisfy the ACL only when the action's owning
   service explicitly supplies the matching owner metadata.
11. For assigned actions, require an exact workspace/subject/version context and
    a matching active human assignment.
12. Enforce separation of duties: `HIGH` requires three distinct human gate
    assignments and excludes a material author/operator from Code Readiness;
    `STANDARD` overlap requires an explicit policy-exception reference; `LOW`
    overlap requires the workflow's affirmative `low_risk_overlap_allowed`.
13. For target-controlled actions, require an exact workspace-bound target in a
    non-empty allowlist. An empty required allowlist denies.
14. Require service authorization for service actors. Absence produces
    `SERVICE_AUTHORIZATION_REQUIRED`; identity/workspace/action/time-shape
    mismatch produces `SERVICE_AUTHORIZATION_INVALID`; inactive/revoked state
    produces `SERVICE_AUTHORIZATION_INACTIVE`; and a trusted time at or after
    expiry produces `SERVICE_AUTHORIZATION_EXPIRED`. A valid authorization has
    exact workspace/service/action identity and
    `issued_at <= trusted_now < expires_at`. Human, system, and agent inputs must
    carry no service authorization.
15. Reject any core action marked as an external side effect. M0-03 performs no
    provider, VCS, model, sandbox, deployment, or network mutation.
16. Return the first deny reason by manifest precedence plus every other matched
    safe reason in that same order. `ALLOW` returns the manifest projection only.

`REQUIRE_HUMAN_CONFIRMATION` is a contract value for future approved policy
versions. No v1 action emits it, and it never exposes a permitted projection.

## Lookup and response contract

The request path is:

1. Resolve the requested workspace through Plane and authenticate the subject.
2. For a human, resolve active membership for that exact workspace. For a
   service, resolve its exact workspace-scoped authorization and leave membership
   absent.
3. Query safe resource metadata with both `workspace_id` and resource ID. If it
   is absent, preserve only the requested ref with `exists=false`; never query by
   child ID globally.
4. Evaluate and durably record the policy decision.
5. On `ALLOW`, load only the named permitted projection or execute the authorized
   command. On any other effect, perform no domain or external side effect.

For Curve routes, a Curve-specific permission/authorization adapter performs
this path before the view or domain service loads protected state. It queries the
same Plane `Workspace`/`WorkspaceMember` authority but does not delegate the final
decision to Plane's generic `WorkspaceMemberPermission`, because the Curve
decision/audit pair is part of this contract. The existing Plane permission
class remains unchanged and all non-Curve routes keep their current behavior.

A missing resource under the authorized workspace returns `404`. A resource ID
that exists only in another workspace also returns `404`; code must not perform a
global fallback lookup. A known in-workspace ACL/role denial returns `403`. A
stale aggregate version remains `412` after authorization. Error bodies use
stable Problem Details and never expose resource owner, ACL, classification,
role, assignment, provider metadata, or the full reason list.

Known cross-workspace probes append a safe `DENY` decision and audit record in
the requested workspace through the trusted service boundary. An unknown
workspace that has no workspace UUID cannot create a workspace-scoped row; it
emits only the existing redacted authentication/security signal with the request
correlation ID.

## Transactions and audit binding

For an allowed mutation, one PostgreSQL transaction must:

1. lock/read the current workspace-scoped aggregate version;
2. evaluate and insert `PolicyDecision`;
3. apply the domain mutation;
4. append `DomainEvent` and any outbox item;
5. append `AuditEvent` with `policy_decision_ref` pointing to the exact decision;
6. commit all records together.

For a denied mutation or query, a separate minimal transaction inserts the
`PolicyDecision` and a safe `AuditEvent` with outcome `DENIED`; it creates no
Operation, DomainEvent, OutboxEvent, InboxMessage, or IdempotencyRecord. If the
decision/audit transaction cannot commit, the protected operation fails closed.

The canonical `input_digest` is:

```text
sha256(
  UTF8("curve-policy-input:v1\0") ||
  UTF8(JSON.stringify(recursively-key-sorted validated input))
)
```

Arrays preserve contract order except semantic sets (`roles`, ACL principal/role
sets, assignments, authors, allowed actions, and allowed targets), which are
sorted by canonical JSON bytes before hashing. Raw idempotency keys and
protected bodies never enter this input or digest.

## Migration and rollback

The Plane implementation adds one additive Curve migration after M0-S2. It
creates only `curve_policy_decision` and its indexes/constraints. Forward,
backward, and forward migration must pass against a disposable PostgreSQL
database. Existing Plane tables and migrations remain unchanged.

Rollback before shipment:

1. disable Curve;
2. stop new Curve API commands;
3. preserve exported safe decision/audit evidence for review;
4. reverse the new Curve migration only in the disposable/local rollback test;
5. revert the implementation commit.

The persistent local Plane stack uses feature disablement and code revert; it
does not require a destructive down-migration. A later shipped environment uses
an additive compensating migration and retention decision D-009 (retention,
backup, legal-hold, tombstone, and erasure policy).

## Required verification

1. Every schema fixture and the exact core manifest validates.
2. Manifest actions and deny reasons are unique; no action allows `AGENT`; every
   action has `external_side_effect=false`.
3. Anonymous, inactive-member, wrong-workspace, unknown-action, missing-role,
   disallowed-environment, disallowed-classification, missing/deny ACL,
   assignment mismatch, separation violation, empty/incorrect target allowlist,
   and absent/expired service authorization each deny with no side effect.
4. `UNKNOWN` classification produces `RESTRICTED` in the decision.
5. ACL allow cannot grant an action denied by role; deny overrides owner/role
   allow.
6. `HIGH`, `STANDARD`, and `LOW` separation fixtures implement the exact rules
   above.
7. Cross-workspace metadata lookups never issue a global child-ID query and do
   not reveal existence.
8. Allowed and denied decisions are immutable, workspace-scoped, sequence-
   unique, recording-attributed, schema-valid, and linked from their audit events.
9. A decision whose `recorded_at` precedes `evaluated_at` is rejected.
10. A public request that attempts to inject role, ACL, assignment,
    classification, allowlist, service authorization, manifest digest, or
    effective-principal context cannot alter the trusted resolved input.
11. A forced decision/audit write failure prevents the protected command.
12. No policy input, decision, audit, log, exception, or test artifact contains
    protected bodies, credentials, raw idempotency keys, or unauthorized ACL
    details.
